7. Git / GitHubを使う

ゲームのソースコードはGitで管理し、 GitHubを使ってチーム内で共有します。

この章では、GitHubへSSHで接続し、 ソースコードを取得・変更・共有するまでの基本的な流れを紹介します。

この章について

Gitには非常に多くの機能がありますが、 最初からすべて覚える必要はありません。 ここでは今回の開発でよく使う操作に絞って説明します。

7.1 GitとGitHub

Gitは、 ファイルの変更履歴を管理するためのバージョン管理システムです。

GitHubは、 Gitで管理しているリポジトリをオンラインで共有できるサービスです。

大まかには次のような関係です。

自分のPC
   │
   │ Gitで変更履歴を管理
   ↓
ローカルリポジトリ
   │
   │ git push
   ↓
GitHub

GitHubに置かれているリポジトリを自分のPCへ取得したり、 自分が行った変更をGitHubへ送ったりしながら開発を進めます。

7.2 Gitの初期設定

Gitでcommitを作成するときには、 誰が変更したのかを記録するための名前とメールアドレスが必要です。

まず現在の設定を確認します。

git config --global user.name
git config --global user.email

まだ設定されていない場合は、次のように設定します。

git config --global user.name "Your Name"
git config --global user.email "your_email@example.com"

GitHubでcommitを自分のアカウントと関連付けたい場合は、 GitHubアカウントに登録しているメールアドレスを使用します。

メールアドレスを公開したくない場合

GitHubでは、commit用の非公開メールアドレスを利用することもできます。 詳しくはGitHubのメールアドレス設定を確認してください。

7.3 SSHでGitHubへ接続する

このチュートリアルでは、 GitHubとの通信にSSHを使用します。

SSHでは、自分のPCに 秘密鍵と公開鍵の組を作成し、 公開鍵だけをGitHubへ登録します。 

WSL
├── 秘密鍵  ← 自分だけが持つ
└── 公開鍵  ─────────→ GitHubへ登録

SSH鍵がすでにあるか確認する

まず、SSH用のディレクトリを確認します。

ls ~/.ssh

例えば、 id_ed25519 と id_ed25519.pub がすでに存在する場合は、 既存のSSH鍵を使える可能性があります。

秘密鍵を共有しない

id_ed25519 は秘密鍵です。 GitHubへ登録するのは id_ed25519.pub のように .pub が付いた公開鍵だけです。

SSH鍵を作成する

SSH鍵がない場合は、次のコマンドで作成します。

ssh-keygen -t ed25519 -C "your_email@example.com"

保存場所を聞かれたら、 特に変更する必要がなければEnterを押して デフォルトの場所を使用できます。

続いてパスフレーズの入力を求められます。 パスフレーズを設定する場合は、 忘れないように管理してください。

作成すると、通常は次の2つのファイルができます。

~/.ssh/id_ed25519
~/.ssh/id_ed25519.pub

ssh-agentへ鍵を追加する

SSH鍵を利用できるように、 ssh-agent を起動します。 

eval "$(ssh-agent -s)"

作成した秘密鍵を追加します。

ssh-add ~/.ssh/id_ed25519

公開鍵をGitHubへ登録する

次のコマンドで公開鍵の内容を表示します。

cat ~/.ssh/id_ed25519.pub

表示された内容をすべてコピーします。

GitHubで次の場所を開きます。

  1. GitHub右上のプロフィール画像をクリック
  2. Settingsを開く
  3. SSH and GPG keysを開く
  4. New SSH keyを選ぶ
  5. 先ほどコピーした公開鍵を登録する

Titleには、 WSL や My PC など、 どのPCの鍵なのか分かる名前を付けておくと便利です。

接続を確認する

公開鍵を登録できたら、 次のコマンドでGitHubへの接続を確認します。 

ssh -T git@github.com

初めて接続するときは、 GitHubのホスト鍵を信頼するか確認される場合があります。

GitHubへの認証に成功したことを示すメッセージが表示されれば準備完了です。

7.4 リポジトリをcloneする

GitHub上にあるリポジトリを自分のPCへ取得する操作を clone と呼びます。

GitHubのリポジトリページで Codeをクリックし、 SSHを選択すると、 次のようなURLが表示されます。 

git@github.com:organization/repository.git

作業用ディレクトリへ移動してから、 git clone を実行します。 

cd ~/projects
git clone git@github.com:organization/repository.git

cloneが完了すると、 リポジトリ名と同じディレクトリが作成されます。 

cd repository

現在の状態は次のコマンドで確認できます。

git status

7.5 基本的なGit操作

開発中によく使う基本的な流れは次のようになります。

ファイルを編集する
    ↓
git status
    ↓
git add
    ↓
git commit
    ↓
git push

変更を確認する

git status

変更されたファイルや、 まだGitで管理されていないファイルなどを確認できます。

commitするファイルを選ぶ

変更したファイルをcommitの対象に追加します。

git add src/main.ts

現在のディレクトリ以下の変更をまとめて追加する場合は、 次のようにも書けます。 

git add .

git add を実行したあとも、 git status で状態を確認できます。

commitを作る

git commit -m "feat: add player movement"

commitは、その時点での変更を履歴として記録する操作です。

メッセージには、 「何を変更したのか」が後から分かる内容を書くようにします。

GitHubへ送る

git push

ローカルで作成したcommitがGitHubへ送られます。

GitHub側の変更を取得する

git pull

他のメンバーがGitHubへ送った変更などを、 自分のローカルリポジトリへ取り込みます。

困ったらまず git status

Gitで現在どういう状態になっているか分からなくなった場合は、 まず git status を確認するのがおすすめです。

7.6 branchを使う

チーム開発では、 main branchを直接編集するのではなく、 作業ごとに新しいbranchを作る方法がよく使われます。

例えば、プレイヤーの移動を実装する場合は、 次のようにbranchを作れます。 

git switch -c feature/player-movement

現在のbranchは次のコマンドで確認できます。

git branch

ファイルを編集してcommitしたら、 新しいbranchをGitHubへ送ります。 

git push -u origin feature/player-movement

最初のpushで -u origin ... を指定しておくと、 その後は同じbranchで単に git push と実行できます。

main に戻る場合は次のようにします。

git switch main

GitHub側の最新の変更を取り込む場合は、 必要に応じて次のようにします。 

git pull

7.7 Pull Request

branchをGitHubへpushしたら、 Pull Requestを作成できます。

Pull Requestを使うと、 自分のbranchで行った変更を main へ取り込む前に、 他のメンバーに内容を確認してもらえます。 

feature/player-movement
          │
          │ Pull Request
          ↓
        main

基本的な流れは次のようになります。

  1. 作業用branchを作る
  2. ファイルを編集する
  3. 変更をcommitする
  4. branchをGitHubへpushする
  5. GitHub上でPull Requestを作る
  6. 必要に応じてレビューや修正を行う
  7. 問題がなければmainへmergeする

チームで同じコードを編集する場合は、 大きな変更を一度に行うより、 内容ごとにbranchやPull Requestを分けると確認しやすくなります。

commitはこまめに作る

いくつもの無関係な変更を1つのcommitにまとめるより、 「プレイヤー移動を追加」 「敵を追加」 のように意味のある単位でcommitしておくと、 後から履歴を追いやすくなります。
