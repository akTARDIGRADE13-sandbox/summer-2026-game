8. GitHub Pagesで公開する

作成したWebサイトは、 GitHub Pagesを使ってインターネット上に公開できます。

今回は、main branchへpushしたときにGitHub Actionsで自動的にビルドし、 GitHub Pagesへデプロイするように設定します。 

ローカルで開発
    ↓
git push
    ↓
GitHub Actions
    ↓
npm run build
    ↓
dist/
    ↓
GitHub Pages

8.1 production build

開発中は次のコマンドで開発サーバを起動していました。 

npm run dev

公開するときは、開発用のファイルをそのまま置くのではなく、 production用にビルドします。 

npm run build

ビルドに成功すると、通常は dist/ ディレクトリが作成されます。 

dist/
├── index.html
├── assets/
└── ...

GitHub Pagesには、この dist/ の内容を公開します。

pushする前にbuildを確認する

GitHub Actions上で初めてエラーに気付くより、 先にローカルで npm run build を実行しておくと問題を見つけやすくなります。

ビルドしたページをローカルで確認したい場合は、 次のコマンドも利用できます。 

npm run preview

8.2 Viteのbaseを設定する

GitHub Pagesでは、リポジトリ名によって公開URLが変わります。

例えば、リポジトリ名が my-game の場合、Project Pagesでは次のような形になります。 

https://<user-or-organization>.github.io/my-game/

このようにルート直下ではなく /my-game/ 以下へ公開されるため、 Viteにもそのパスを設定します。

vite.config.ts に base を追加します。 

import { defineConfig } from "vite";

export default defineConfig({
  base: "/my-game/",
});

このサンプルリポジトリでは名前が summer-2026-game なので、次のように設定しています。 

base: "/summer-2026-game/",
baseを忘れると

HTML自体は表示されても、 JavaScriptやCSSなどのファイルを正しい場所から読み込めず、 ページが崩れたりゲームが動かなかったりすることがあります。

8.3 GitHub Pagesを有効にする

GitHub上で、公開したいリポジトリを開きます。

  1. Settingsを開く
  2. Pagesを開く
  3. Build and deploymentを確認する
  4. SourceをGitHub Actionsにする

これで、GitHub ActionsからGitHub Pagesへ デプロイできるようになります。

Organizationのリポジトリでも利用できます

GitHub PagesはOrganization配下のリポジトリでも利用できます。 ただし、Organization側の設定によってPagesの利用が制限されている場合があります。

8.4 Workflowを作る

GitHub Actionsの設定ファイルを作ります。 

.github/
└── workflows/
    └── deploy.yml

.github/workflows/deploy.yml を次のようにします。 

name: Deploy to GitHub Pages

on:
  push:
    branches:
      - main

  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}

    runs-on: ubuntu-latest

    steps:
      - name: Checkout
        uses: actions/checkout@v7

      - name: Setup Node.js
        uses: actions/setup-node@v7
        with:
          node-version: lts/*
          cache: npm

      - name: Install dependencies
        run: npm ci

      - name: Build
        run: npm run build

      - name: Setup Pages
        uses: actions/configure-pages@v6

      - name: Upload artifact
        uses: actions/upload-pages-artifact@v5
        with:
          path: ./dist

      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v5

このWorkflowでは、main branchへpushされるたびに 次の処理が自動で実行されます。

  1. リポジトリを取得する
  2. Node.jsを準備する
  3. npm ciでパッケージをインストールする
  4. npm run buildを実行する
  5. dist/をGitHub Pages用にアップロードする
  6. GitHub Pagesへデプロイする

npm ciとは

ローカルでは npm install を使いましたが、CIでは npm ci を使っています。

package-lock.json に記録された内容を使って、 再現性の高い形でパッケージをインストールするためのコマンドです。

詳しい違いを今覚える必要はありません。 GitHub ActionsなどのCI環境では npm ci を使う、くらいに考えておけば十分です。

8.5 デプロイする

Workflowを追加したらcommitしてGitHubへpushします。 

git add .
git commit -m "ci: deploy site to GitHub Pages"
git push

GitHubのリポジトリページで Actionsを開くと、 Workflowの実行状況を確認できます。 

Checkout
   ↓
Setup Node.js
   ↓
Install dependencies
   ↓
Build
   ↓
Upload artifact
   ↓
Deploy to GitHub Pages

すべて成功すれば、GitHub PagesのURLから Webサイトへアクセスできるようになります。

以降はmain branchへ変更をpushするたびに、 同じWorkflowが実行され、公開サイトも更新されます。

8.6 うまくいかない場合

まずローカルでbuildする

ActionsでBuildが失敗した場合は、 まずローカルで同じコマンドを実行します。 

npm run build

TypeScriptのエラーや、 存在しないファイルへの参照などがあると buildに失敗します。

Pagesが有効になっていない

次のようなエラーが表示される場合があります。 

Get Pages site failed.
Please verify that the repository has Pages enabled
and configured to build using GitHub Actions.

この場合は、 GitHubの Settings → Pages を開き、 Sourceが GitHub Actions になっているか確認してください。

ページは開くがCSSやJavaScriptが読み込まれない

GitHub Pages上だけ表示が崩れる場合は、 vite.config.ts の base を確認してください。 

export default defineConfig({
  base: "/<repository-name>/",
});

GitHub Actionsだけ失敗する

ローカルでは普段開いていないページでも、 production buildではすべてのエントリが処理されます。

削除済みのTypeScriptファイルやCSSを 古いHTMLがまだ参照していないか確認してください。 

rg '削除したファイル名' .
