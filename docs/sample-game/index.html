6. サンプルゲームを読む

このサイトには、p5.jsとTypeScriptを使って作成した シンプルなサンプルゲームが含まれています。

プレイヤーを操作して敵を避けながらアイテムを集め、 スコアを増やしていくゲームです。 まず実際にプレイしてからコードを読むと、 それぞれの処理が何をしているのか理解しやすくなります。

サンプルゲームをプレイする

この章について

この章ではTypeScriptの文法そのものは詳しく説明しません。 それぞれのファイルや処理が 「ゲームの中で何を担当しているか」を中心に見ていきます。

6.1 ゲーム全体の構成

ゲームに関するソースコードは src/game/ にまとめています。 

src/game/
├── main.ts
├── Game.ts
├── Player.ts
├── Enemy.ts
├── Item.ts
└── constants.ts

それぞれの役割は次のようになっています。

ファイル 役割
main.ts p5.jsを起動し、ゲーム全体と接続する
Game.ts ゲーム全体の状態・更新・描画を管理する
Player.ts プレイヤーの移動と描画を管理する
Enemy.ts 敵の生成・移動・衝突判定を管理する
Item.ts アイテムの配置と取得判定を管理する
constants.ts Canvasサイズや移動速度などの定数をまとめる

大まかな関係は次のようになっています。

p5.js
  │
  ↓
main.ts
  │
  ↓
Game
├── Player
├── Enemy[]
└── Item

main.ts にゲームの処理をすべて書くのではなく、 役割ごとにファイルを分けることで、 コードを追いやすくしています。

6.2 main.ts

main.ts は、 p5.jsとゲーム本体を接続する入口です。

主要な部分は次のようになっています。

new p5((p) => {
  let game: Game;

  p.setup = () => {
    const canvas = p.createCanvas(
      CANVAS_WIDTH,
      CANVAS_HEIGHT,
    );

    canvas.parent("game-container");

    game = new Game(p);
  };

  p.draw = () => {
    game.update();
    game.draw();
  };

  p.keyPressed = (event) => {
    // キー入力をGameへ渡す
  };
});

setup() ではCanvasを作り、 Game を初期化しています。

draw() では毎フレーム、 ゲームの状態を更新してから画面を描画します。 

game.update();
game.draw();

このように、 p5.js固有の処理とゲーム本体の処理を分離しています。

6.3 Game.ts

Game はゲーム全体を管理するクラスです。

例えば、次のような情報を保持しています。

private player: Player;
private item: Item;
private enemies: Enemy[] = [];

private enemySpawnTimer = 0;
private score = 0;
private state: GameState = "title";

プレイヤー、アイテム、敵だけでなく、 スコアや現在のゲーム状態も Game がまとめて管理しています。

ゲームの状態

ゲームには3つの状態があります。

type GameState = "title" | "playing" | "gameOver";
状態 意味
title ゲーム開始前
playing ゲームをプレイしている
gameOver 敵に接触してゲームが終了している

状態は次のように変化します。

title
  │ Space
  ↓
playing
  │ 敵に接触
  ↓
gameOver
  │ R
  ↓
playing

更新と描画

Game でも、 処理を大きく update() と draw() に分けています。 

update(): void {
  // プレイヤーを動かす
  // アイテム取得を確認する
  // 敵を生成する
  // 敵を動かす
  // 衝突を確認する
}

draw(): void {
  // 背景を描く
  // プレイヤーを描く
  // 敵を描く
  // アイテムを描く
  // スコアなどを描く
}

「ゲームの状態を変える処理」と 「現在の状態を画面へ描く処理」を分けておくと、 コードの役割が分かりやすくなります。

6.4 Player.ts

Player は、 プレイヤーの位置を保持し、 キー入力に応じて位置を更新します。

例えば、移動方向を次のように求めています。

let dx = 0;
let dy = 0;

if (p.keyIsDown(p.LEFT_ARROW) || p.keyIsDown(65)) {
  dx -= 1;
}

if (p.keyIsDown(p.RIGHT_ARROW) || p.keyIsDown(68)) {
  dx += 1;
}

if (p.keyIsDown(p.UP_ARROW) || p.keyIsDown(87)) {
  dy -= 1;
}

if (p.keyIsDown(p.DOWN_ARROW) || p.keyIsDown(83)) {
  dy += 1;
}

ここで使用している 65、 68、 87、 83 は、それぞれA、D、W、Sキーに対応します。

斜め移動を正規化する

例えば右と上を同時に入力すると、 移動方向は (1, -1) になります。

このままでは斜め方向だけ移動速度が速くなってしまうため、 ベクトルの長さを1に揃えています。 

const length = Math.hypot(dx, dy);

if (length > 0) {
  dx /= length;
  dy /= length;
}

その後、移動速度と経過時間を使って位置を更新します。

const dt = p.deltaTime / 1000;

this.x += dx * PLAYER_SPEED * dt;
this.y += dy * PLAYER_SPEED * dt;

最後に constrain() を使って、 プレイヤーがCanvasの外へ出ないようにしています。

6.5 Enemy.ts

敵はCanvasの外側から出現し、 出現した瞬間のプレイヤーの位置へ向かって直進します。

出現する場所を決める

random() を使って、 上・右・下・左のどの辺から出現するかをランダムに決めます。 

const edge = Math.floor(p.random(4));

switch (edge) {
  case 0:
    // top
    break;

  case 1:
    // right
    break;

  case 2:
    // bottom
    break;

  default:
    // left
    break;
}

進行方向を決める

敵の位置からプレイヤーの位置へ向かうベクトルを作ります。

let dx = targetX - this.x;
let dy = targetY - this.y;

const length = Math.hypot(dx, dy);

dx /= length;
dy /= length;

this.vx = dx * ENEMY_SPEED;
this.vy = dy * ENEMY_SPEED;

この方向は敵を生成したときに一度だけ決まるため、 プレイヤーがその後移動しても敵は曲がりません。

一定時間ごとの敵生成は Game 側で管理しています。

6.6 Item.ts

アイテムはCanvas内のランダムな位置に配置されます。

this.x = p.random(
  ITEM_RADIUS,
  CANVAS_WIDTH - ITEM_RADIUS,
);

this.y = p.random(
  ITEM_RADIUS,
  CANVAS_HEIGHT - ITEM_RADIUS,
);

プレイヤーがアイテムに触れるとスコアを1増やし、 アイテムを別の場所へ再配置します。 

if (this.item.collidesWith(this.p, this.player)) {
  this.score += 1;
  this.item.respawn(this.p);
}

今回はサンプルを単純にするため、 アイテムは同時に1個だけ存在します。

6.7 constants.ts

ゲームで使用する数値の一部は、 constants.ts にまとめています。 

export const CANVAS_WIDTH = 640;
export const CANVAS_HEIGHT = 480;

export const PLAYER_RADIUS = 15;
export const PLAYER_SPEED = 250;

export const ENEMY_RADIUS = 15;
export const ENEMY_SPEED = 120;

export const ITEM_RADIUS = 10;
export const ENEMY_SPAWN_INTERVAL = 1000;

例えばプレイヤーを速くしたければ、 PLAYER_SPEED を変更するだけで済みます。

ゲームの調整に使う値をまとめておくことで、 コードの中から数値を探して変更する必要がなくなります。

6.8 入力処理

このゲームでは、キー入力を2種類の方法で扱っています。

方法 用途
keyIsDown() キーを押している間、連続して処理する
keyPressed() キーが押された瞬間に一度だけ処理する

プレイヤーの移動には、 キーを押している間ずっと動かしたいので keyIsDown() を使用します。

一方で、ゲーム開始やリスタートには keyPressed() を使用します。 

keyPressed(): boolean {
  if (this.state === "title" && this.p.key === " ") {
    this.state = "playing";
    return true;
  }

  if (
    this.state === "gameOver" &&
    (this.p.key === "r" || this.p.key === "R")
  ) {
    this.reset();
    this.state = "playing";
    return true;
  }

  return false;
}

ブラウザのスクロールを防ぐ

矢印キーやSpaceには、 Webページをスクロールするというブラウザ標準の動作があります。

ゲームでこれらのキーを使用するときは、 preventDefault() を使って標準動作を止めています。 

if (handled || (game.isPlaying() && isMovementKey)) {
  event.preventDefault();
}

6.9 衝突判定

今回はプレイヤー、敵、アイテムを円として描いているため、 円同士の中心間距離を使って衝突を判定できます。

2つの円が衝突している条件は、 中心間距離が半径の和より小さいことです。 

const distance = p.dist(
  this.x,
  this.y,
  player.x,
  player.y,
);

return distance < ENEMY_RADIUS + PLAYER_RADIUS;

dist() は2点間の距離を計算する p5.jsの関数です。

中心間距離 < 半径1 + 半径2
            ↓
          衝突

アイテムとの衝突判定も同じ方法を使っています。

6.10 改造してみる

サンプルコードが動いたら、 数値や処理を少し変更して動作がどう変わるか試してみてください。

簡単

  • プレイヤーの色を変える
  • プレイヤーの移動速度を変える
  • 敵の移動速度を変える
  • Canvasの大きさを変える
  • 敵が出現する間隔を変える

少し発展

  • 時間が経つほど敵を速くする
  • 敵の大きさをランダムにする
  • アイテムの種類を増やす
  • HPを追加して数回まで敵に当たれるようにする
  • 一定スコアごとに難しくする

さらに発展

  • 画像を使ってキャラクターを描画する
  • 効果音やBGMを追加する
  • 弾を撃てるようにする
  • 新しい種類の敵を作る
  • マウスを使った操作を追加する

サンプルゲームと同じ構造にする必要はありません。 作りたいゲームに合わせて、 必要な処理やファイル構成を自由に変更してみてください。
